How the map is built

  1. Read goals, replies, tool activity, and validation provenance from compatible local sessions.
  2. Group related work from different sessions and tools by project.
  3. Organize separate goals into voyages while retaining working, failed, reverted, and conflicting branches.
  4. Link waypoints back to available original sessions, file changes, and validation.

Evidence boundary

Wayfinder creates a file change only when the source record contains evidence of a genuinely successful edit. Unfinished, failed, or out-of-bounds tool calls do not become file changes, and the app does not infer a nonexistent historical diff from the current workspace.

Collection, grouping, and map generation happen locally. The current version has no account, telemetry, cloud sync, or cloud analysis.
